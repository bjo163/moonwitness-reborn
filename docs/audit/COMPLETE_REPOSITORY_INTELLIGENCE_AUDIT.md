### Source-level inspection of the selected repository

The primary-repository decision is ratified; the source audit is still partial. The following findings were checked directly in the selected checkout:

- Addon models are registered in `ql_base`, `ql_auth`, `ql_chat`, and `ql_ai`; manifests declare dependencies and ACLs. `res.users`/`res.sessions` are admin-only for generic CRUD, `chat.message` denies all user CRUD and is accessed through server-side service methods, and provider user CRUD is read-only through generic ACL. `ql_auth` embeds its user list view in the manifest; private fields are filtered from model metadata and normal QlOrm records.

Message records have no owner field or foreign-key declaration; the current store first checks that the parent conversation belongs to the caller, then queries/deletes messages by `conversation_id`. These are domain responsibilities to reconcile into addon services while retaining API request-shape and body-size checks.

Authenticated model metadata filters private fields/views and calculates permissions from the addon registry.
- `packages/database/src/index.ts` is a domain-specific store, not merely a low-level connection adapter: its interface and implementation own user, session, conversation, and message operations and conversation title/update behavior. This is the clearest current ownership mismatch with the project rules.
- Package-local test discovery found tests for `ql-orm`, but no tests inside the four `ql_*` addon packages. The existing workspace tests do not establish the requested per-addon manifest/model/ACL, cross-user, private-field, and internal-service guarantees.
