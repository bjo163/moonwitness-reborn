## Companion documents and machine checks

These exist to keep the register honest; none of them is a D-numbered deliverable and none defines a status this register does not already carry.

- `docs/audit/PROMPT_COVERAGE_AND_STEP8_REPORT.md` is the `masterprompt.md` FINAL ASSIGNMENT STEP 8 report (its twelve required items plus the A–I acceptance-criteria walk). It states verdicts and quotes gate output; it deliberately does not restate the per-deliverable statuses above, and it names this register as the place status lives.
- `docs/audit/tools/prompt_coverage_gate.py` re-reads `masterprompt.md` itself and checks the baseline against it offline: the §4.3 ownership matrix, the §4.4 twenty attributes, PHASE 0–12 headings, the 87 PHASE 0–7 planning items and their carriers/status/gap links, all 13 uncovered-item-to-TODO-goal links, all 35 numbered build items plus the two prose-only PHASE 9/10 goals (37 total), the A–I criteria, the twelve items STEP 8 demands of the report, the D01–D31 paths in this register, every `ql_*` owner token used in D02, the prose tallies, the ROCKSOUL family views, the migration-decision counts, D03's own entry bookkeeping, the mirrored blocker lists, and the git state of the canonical documents (whether each is in **HEAD** or merely staged, the branch, its upstream, the unpushed count, the tracked-modified count, HEAD, `origin/main`, ahead/behind, tags). Like the census gate it is a **manual** run: neither gate is wired into `.github/workflows/`, so a pass must be re-established by executing the script.
- `docs/audit/tools/repository_census_gate.py` is the census gate: it re-queries the three GitHub sources, diffs the live union census against the D02 table, requires each census SHA to appear literally, and enforces that the estate-wide roll-up assigns every matrix row exactly once with a non-empty owner. It needs authenticated `gh`, so it is a manual run, not a per-commit gate.
- Both blocker lists — the eighteen items in `docs/audit/ARCHITECTURE_AND_DOCUMENTATION_RECONCILIATION.md` and the eighteen mirrored in `TODO.md` §5 — are checked item-by-item for the same count and the same R-numbers, because two lists that drift would be competing definitions of what blocks implementation. `docs/audit/ARCHITECTURE_AND_DOCUMENTATION_RECONCILIATION.md` is the authority; `TODO.md` is the working queue that restates it. The count itself is printed by the gate, not kept in this sentence.
